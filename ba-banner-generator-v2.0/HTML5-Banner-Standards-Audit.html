Executive Summary

The BetAnything v2.0 HTML5 banner templates have been evaluated against the current standards set by the IAB (Interactive Advertising Bureau), Google Ad Manager, Display & Video 360 (DV360), and Adform. These standards govern how HTML5 creatives must be structured in order to be accepted and trafficked across programmatic advertising platforms.

The creative approach — real HTML/CSS layout, embedded fonts, inline SVG logo, local video, and CSS animations — is architecturally sound and modern. Five core requirements are already met. Four technical items must be resolved before the banners can be submitted to any DSP or ad server. None of the issues require a redesign; all are implementation-level fixes that can be completed quickly.

Passing Standards

Character encoding declared Pass

Requirement

Every HTML5 creative must declare UTF-8 encoding in its <head>. This prevents character rendering issues across browsers and ad servers in different regions.

Current status

<meta charset="UTF-8"> is present at the top of all templates. No action needed.

Ad border (1px) present Pass

Requirement

IAB and Google require a visible 1px border when the ad background colour is white or could blend into a page background. This ensures the ad unit boundary is always visible to users.

Current status

All templates have border: 1px solid #ffffff on the banner shell. Compliant.

No external CDN or third-party calls Pass

Requirement

Ad servers require all assets to be self-contained. External calls to Google Fonts, CDN-hosted libraries, or remote images are blocked by most DSPs and cause creative rejection or broken rendering.

Current status

Fonts are base64-embedded, the logo is inline SVG, and the video is locally referenced. Zero external dependencies.

Entrance animations play once only Pass

Requirement

IAB guidelines state that intro animations (logo, copy, CTA entrance sequences) must not loop. Repeated flashing entrance animations are penalised by Google and considered disruptive to users.

Current status

All entrance animations use animation-iteration-count: 1 (the default). They play once and hold on the final frame via fill-mode: both. Compliant.

Video is muted and does not autoplay audio Pass

Requirement

IAB LEAN standards and all major DSPs prohibit auto-playing audio in display ads. Video used as a background must be muted and may not initiate sound without explicit user interaction.

Current status

All video elements use autoplay muted loop playsinline. Audio will never fire automatically. Compliant.

Issues — Action Required

clickTag not implemented — entire ad must be clickable Critical

Why this matters

The clickTag is the mechanism ad servers use to track clicks and redirect users to the advertiser's landing page. Without it, the banner cannot be trafficked on any DSP (Google, DV360, TradeDesk, Adform). It is the single most common reason for creative rejection. Additionally, the clickable area must cover the entire banner — not just the CTA button — as per IAB and Google policy. Button-only click zones are rejected.

Required fix

Add a clickTag variable and wrap the banner in a full-size anchor tag:

<script> var clickTag = ""; </script> <a href="javascript:void(0)" onclick="window.open(clickTag)" style="position:absolute; inset:0;z-index:99;"> </a>
Looping animations must stop at 30 seconds Required

Why this matters

IAB guidelines and Google Ad Manager enforce a 30-second maximum for any animation cycle. Banners with animation: infinite beyond 30 seconds are flagged as disruptive. The copy fade loop and the CTA glow currently run indefinitely. Both must stop — or freeze on their last frame — at the 30-second mark.

Required fix

Use JavaScript to remove animation classes after 30 seconds, or calculate a finite iteration-count for each animation so the total runtime stays within 30s.

setTimeout(() => { document.querySelector('.copy-1') .style.animation = 'none'; document.querySelector('.copy-2') .style.animation = 'none'; document.querySelector('.cta') .style.animation = 'none'; }, 30000);
Entry point must be named index.html Required

Why this matters

All major ad servers (Google Ad Manager, DV360, Adform, Sizmek) require the main HTML file to be named index.html and placed at the root of the ZIP archive. A file named 300x600.html will be rejected during upload validation on most platforms.

Required fix

Rename 300x600.html → index.html before packaging into a ZIP for delivery. The current filename is fine for internal development and preview; the rename happens at export time.

Ad size meta tag missing Required

Why this matters

Google Ad Manager requires a <meta name="ad.size"> tag in the <head> of every creative. This allows the ad server to validate that the declared dimensions match the line item targeting. Creatives without this tag may not render correctly or may fail validation.

Required fix

Add the following inside <head> of each template, adjusted per size:

<!-- 300x600 --> <meta name="ad.size" content="width=300,height=600"> <!-- 728x90 --> <meta name="ad.size" content="width=728,height=90">

Advisory — Best Practice

Initial file size may exceed 150KB limit on some platforms Advisory

Context

Google Ads and many DSPs enforce a 150KB initial load limit for HTML5 creatives. The two Aeonik OTF fonts embedded as base64 add approximately 215KB of data. DV360 allows a polite load of up to 5MB, so this is not a universal blocker — but it will cause rejection on stricter platforms such as standard Google Display Network.

Recommended action

Convert the OTF files to WOFF2 format (typically 30–40% smaller) and reference them via relative path inside the ZIP instead of base64-embedding them. This brings font overhead down to ~50KB each and keeps the initial HTML payload well under 150KB.
